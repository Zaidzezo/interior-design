# Assets and licenses

No third-party furniture, textures, photographs, models or HDRIs are bundled in this update. An HTTPS request to https://api.polyhaven.com/assets?t=models was blocked by the execution environment proxy (HTTP 403); no license or TLS checks were bypassed.

## Original local assets

Author: BuildSpace contributors. Source: this repository. License: CC0-1.0 for the generated material maps and generated furniture sprites only (https://creativecommons.org/publicdomain/zero/1.0/).

Each of the following materials has three local assets, `NAME-albedo.webp`, `NAME-normal.webp`, and `NAME-roughness.webp`, under `apps/web/public/assets/materials`: oak, walnut, ash, herringbone, tile, marble, carpet, concrete, terrazzo. All 27 files are procedurally generated by `scripts/generate-materials.py` (requires Pillow). No input photographs or external assets are used. They are approximations, not scanned PBR materials; normal and roughness maps are synthetic. Patterns cover 1.2m per tile. Herringbone is a stylized approximation.

Furniture symbols are original procedural art from packages/core/src/vector.ts and catalog.ts. Soft shadows, directional shading and fabric/wood/stone patterns are generated locally. Models remain procedural geometry; these are not photorealistic imported models. No CC-BY asset is bundled, so no third-party in-app attribution obligation is introduced.

## Manual download list for a future asset import

- Poly Haven models: https://polyhaven.com/models — select seating, tables, beds and storage; verify each asset page and record its asset name and credited author. Poly Haven library license: https://polyhaven.com/license (CC0).
- Poly Haven textures: https://polyhaven.com/textures — oak/walnut planks and parquet, marble, porcelain, concrete, fabric and terrazzo. Download 1K/2K albedo, normal OpenGL and roughness maps and record each asset page/author.
- Kenney furniture: https://kenney.nl/assets/furniture-kit — verify current download license before integration and retain included license.

Do not merely save files in public and expect arbitrary models to work: each imported model needs catalog registration, dimension normalization, orientation, material processing, plan-sprite rendering, matching hit footprint and testing. GLB/Draco/KTX2 pipelines and scanned models have not been delivered in this fallback stage.
